## Should fix
1. **The live mobile check is now dead on the Gold application form.** `common/static/common/js/validate.js:224` reads the CSRF token only from `input[name="csrfmiddlewaretoken"]`, and returns null when there is none. The Gold form is built in JS (`gold-apply.js:156`) and the rendered `/gold-card/apply/` has no such input. I checked the rendered HTML: no `csrfmiddlewaretoken`, but `"mobile": "/validate/mobile/"` is configured. So every mobile check silently returns null, where before (GET) it worked. The server still checks on submit, but the instant feedback (a build standard) is lost. Fix: fall back to the `csrftoken` cookie, like `api.js:4` (`csrfToken()`).
2. **Backfill undoes two hand edits (same class as last round's #2).** I ran it: clear the gym's `detail_image_name` in admin, or remove a Gold perk's `note`, and the next run puts both back (`backfill_site_data.py` `_round_3`: gym block and `"note" not in perk`). `pages/tests/test_round3.py:188-200` asserts this behaviour. Clearing the name is the only way to turn the gym inset off. Fix: fill these only on rows still at their pre-round-3 seeded state (or mark "done" once), and change the test to assert a cleared value stays cleared.
3. **The opener and sign-in alts are typed in templates and can be wrong.**
   - `pages/templates/pages/_spa_opener_pic.html:1` picks one of three fixed alts by `is_door`/name. Any `opener_image` other than robe or door (for example `corridor`) gets "A white robe…". An upload on `spa.intro` also gets the robe or door alt; `intro.image_alt` is ignored.
   - Same in `users/templates/users/_shell_bottom.html` (lockers alt fixed even with an upload).
   - WCAG 1.1.1, and "data from rows". Fix: return `alt` from `opener_picture()` / `signin_shell()` (row `image_alt` first, then a per-name default).
4. **The living still never stops once the Pause button is gone.**
   - `common/static/common/js/spa.js` removed the old `shrunk` guard, so the 24 s yoyo on `.door-still` (and the door video, if one exists) keeps running in the shrunk frame for as long as the scene is in view.
   - `tl.to(button, { autoAlpha: 0 }, 0.15)` hides Pause from 15% of the pin.
   - Last round paused the loop when shrunk for exactly this reason. WCAG 2.2.2 (Pause, Stop, Hide).
   - Fix: restore the "pause when progress > 0.7" trigger, or keep Pause visible while anything moves.
5. **The owner-visible opener request is not met on the live page yet.**
   - The manifest has no `robe` and no `door-wide`, so `opener_picture()` falls through to `door-gold`. That is the zoomed-in door Moishe asked to replace (rows 265 and 269: "Until then a wider realistic photo of the doorway replaces the zoomed-in door").
   - This is an asset gap, not a code bug, but nothing on the page changes for him until a picture is built.
   - Fix: build `robe` (or `door-wide`) before showing Moishe, or say so in the hand-off.
6. **The contract names the wrong towel picture.** `docs/design/ROUND3-CONTRACT.md:30` says `towel-folded`, but the code, seed, tests and AMENITIES.md use `towel-bench` (`pages/services.py:473`, `content/seed.py:51`). A render saved as `towel-folded` would never show. The list also omits `towel-bench-portrait`, `toiletries`/`tote` portraits per AMENITIES 6. Fix: change the contract line to `towel-bench` (+ `-portrait`).
